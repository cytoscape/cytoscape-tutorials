What are Service Apps?

  • A way for you to extend Cytoscape Web functionality.
  • Can be written in any language that supports REST services.
  • Can be run by you locally or served from a remote server.
  • Ability to call from Cytoscape Desktop coming soon.
What are Service Apps? They are a way for you to extend Cytoscape Web functionality. They can be implemented in any language that supports REST services, and can be run by you locally or served from a remote server. REST stands for Representational State Transfer, which is a convention for building web services that are easy to interact with programmatically.

Service Apps vs. Web vs. Desktop Apps

App typeBest forTradeoff
Desktop AppDeep UI integrationDesktop only, requires Java development
Web AppDeep UI integrationWeb only, requires TypeScript / web development
Service AppLanguage-agnosticNo/Limited API access, requires hosting
Here is a comparison of Service Apps, Web Apps, and Desktop Apps. Desktop Apps are best for deep UI integration, but they are desktop only and require Java development. Web Apps are also best for deep UI integration, but they are web only and require TypeScript or web development. Service Apps are language-agnostic, but they have no or limited API access and require hosting.

Service Apps for Cytoscape Web are REST services that implement a specific contract. How Service Apps Work

That looks complicated, but you can vibe a new Service App pretty quickly. The next slides will go over the high level endpoints and show you how to implement a simple Service App with Python and Flask.

Endpoints

Highlevel view of Service App REST endpoints

GET    /              metadata: name, menu item, params, input definition
GET    /status        service health
POST   /              submit task, returns task id
GET    /<taskID>/status  task progress
GET    /<taskID>         final task result
DELETE /<taskID>         cancel/delete task
Here is a high level view of the Service App REST endpoints. The first endpoint returns metadata about the service. The second endpoint returns service health. The third endpoint submits a task to the service and returns a task id. The fourth endpoint returns task progress. The fifth endpoint returns the final task result. The sixth endpoint cancels or deletes a task.

Metadata

Provides information about the service. Called by Cytoscape Web when registering the Service App.

GET    /              metadata: name, menu item, params, input definition
Response 
{
    "serviceInputDefinition": Object (SelectionMethod), # Data wanted
    "cyWebActions": [string], # Data generated
    "cyWebMenuItem": Object (RootMenu), # Menu location
    "name": string, 
    "description": string,
    "showDescriptionInDialog": boolean,
    "author": string,
    "citation": string,
    "version": string,
    "parameters": [ # UI parameters
      Object (Parameter)
    ]
}
The metadata endpoint provides information about the Service App. It is called by Cytoscape Web when registering the Service App. The response includes what data the Service App needs, what data it generates, where should the Service App appear in the menu, and what parameters should be displayed to the user.

Status

Provides information about the health of the Service App. In future will be called by Cytoscape Web and AppStore to monitor service health.

GET    /status        service health
Response Example 
{
  "status": "ok",
  "version": "1.0.0",
  "numberOfRunningTasks": 0
}
The status endpoint provides information about the health of the Service App. It is called by Cytoscape Web and in the future by the AppStore to monitor service health.

Submit task

Submits a task to the Service App. Called by Cytoscape Web when a user clicks Submit on Service App dialog.

POST   /              submit task, returns task id
Request Example 
{
	"parameters":{"someparam": "somevalue"},
	"data":[{"CXVersion": "2.0" ... }]
}
Response Example 
{"id":"9a363a0b-bdc2-40a7-91ba-19657bdac156"}
The submit task endpoint allows Cytoscape Web to submit a task to the Service App. It returns a unique task ID that can be used to query the status and final result of the task.

Task status

Provides information status of a task excluding the final result. Cytoscape Web polls this endpoint waiting for task completion.

GET    /<taskID>/status  task progress
Response Example 
{
	"id":"9a363a0b-bdc2-40a7-91ba-19657bdac156",
	"message":null,
	"progress":100,
	"status":"complete"
}
The task status endpoint provides information about the progress of a task. It is called by Cytoscape Web to monitor the status of a submitted task. The message field can be used to provide additional information about the task status to the user. The progress field contains a value between 0 - 100 indicating how much of the task has been completed. The status field can be submitted, processing, complete, failed.

Task final result

Provides task final result. Called by Cytoscape Web after task is complete.

GET    /<taskID>  task final result
Response Example 
{
	"id":"9a363a0b-bdc2-40a7-91ba-19657bdac156",
	"result": [ {"action": "updateNetwork",
	             "data": [{"CXVersion": "2.0" ... }]} ],
	"message":null,
	"progress":100,
	"status":"complete"
}
The task final result endpoint provides the final result of a completed task. It is called by Cytoscape Web after a task is complete. The result field contains the final output of the task.

Delete task

Deletes a task from the service, called by Cytoscape Web after obtaining result.

DELETE /<taskID>  delete task
Successful deletion has no needed response
The task deletion endpoint removes a task from the service. It is called by Cytoscape Web after obtaining the result of a task. No response body is required for a successful deletion.

Hands-on Exercise

Simple Service App with Python + Flask

Goal: a tiny service that accepts a network, adds a few nodes and returns an updated network.

In this hands-on exercise, we will create a simple Service App using Python and Flask. The goal is to implement a tiny service that accepts a network, adds a few nodes, and returns an updated network.

Developer Checklist

  • Implement required endpoints.
  • Return valid metadata from GET /.
  • Support CORS for Cytoscape Web.
  • Use stable task ids.
  • Return progress, status, message, and result consistently.
  • Keep result actions aligned with Cytoscape Web’s expected result schema.

Visit the Specification for Service App in Cytoscape Web.

Here is a developer checklist for creating a Service App. Implement the required endpoints, return valid metadata from GET /, support CORS for Cytoscape Web, use stable task ids, return progress, status, message, and result consistently, and keep result actions aligned with Cytoscape Web’s expected result schema. Please visit the Specification for Service App in Cytoscape Web for more details.
